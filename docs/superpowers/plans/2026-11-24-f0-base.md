# F0 Base Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Ejecución nativa.

**Goal:** Monorepo verificable con configuración de nicho validada, API con salud y errores uniformes, web mínima y artefactos de despliegue.

**Architecture:** pnpm workspaces; paquetes ESM compilados con `tsc`. La API inyecta siempre con `@Inject(token)` explícito (no depende de metadatos de decoradores). La web solo presenta.

**Tech Stack:** Node 24, TypeScript 6.0.3, Nest 12.6, Next 16.4, Tailwind 4.3, Zod 4.6, Vitest 5.1, ESLint 10.

**Spec:** [marketplace-core-design](../specs/2026-11-24-marketplace-core-design.md)

## Global Constraints

- Archivos JS/JSX/TS/TSX < 500 líneas (`max-lines`).
- El núcleo (`apps/*`, `packages/{core,contracts,ui}`) no contiene términos de nicho.
- Sin secretos en el repo; entorno validado al arrancar.
- Docker solo en Dokploy CT 110; ningún cambio allí sin confirmación.
- Sin CORS; `/api` en el mismo origen. Errores `{ error: { code, message, requestId } }`.
- `postgres`, `redis` y `worker` sin puertos publicados.
- Prisma 7.10.1 entra en F1 con el primer modelo; F0 comprueba Postgres con `pg`.

## Review Focus

- `VERTICAL` desconocido o config inválida: la app no arranca y el mensaje nombra el campo (Tarea 2).
- Categorías duplicadas o padre inexistente en un nicho: rechazo (Tarea 2).
- Postgres o Redis colgado (no caído): `/api/health/ready` responde 503 en ≤ 2 s (Tarea 3).
- Excepción inesperada: 500 sin stack ni mensaje interno (Tarea 3).
- `x-request-id` hostil del cliente: se ignora y se genera otro (Tarea 3).
